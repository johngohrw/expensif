## Decisions & Rationale
1. **Option B for mobile nav** — User chose React island over inline JS for maintainability and future reuse (details panels, right-side drawers). This aligns with the project's islands-first philosophy.
2. **Panel as generic primitive** — Not coupled to nav. `position` and `width` props make it reusable for future features.
3. **Desktop nav stays as Go templates** — Only mobile gets React. Avoids shipping JS for desktop users.
4. **No-JS mobile users** — Won't see nav links. Acceptable tradeoff for an islands-based app.
5. **Scroll lock with padding compensation** — `window.innerWidth - documentElement.clientWidth` measures scrollbar width to prevent layout shift when `overflow: hidden` is applied.
