## Decisions & Rationale
1. **Consumer-owned interface** — `service.RateFetcher` lives in `service`, not `rate`. The consumer defines what it needs; `*rate.Client` structurally satisfies it automatically. This drops the `rate` import from `service.go`.
2. **Synthetic domain structs on error** — Rather than introduce a separate `FormData` struct, we reuse `domain.Expense` and `domain.User` with partial population. The templates already check `{{if .Expense}}` / `{{if .User}}`, so this works with zero template changes.
3. **Append to `.Islands`, don't overwrite** — `basePageData` owns the baseline (`mobile-nav`), handlers append page-specific islands. Makes the island loading fully declarative per handler.
4. **Case-insensitive test assertions** — Validation error messages are capitalized ("Amount must be greater than 0"). Tests now use `strings.ToLower()` for robust substring matching.
5. **Migration fix without new migration** — The `paid_by` fix is in the existing migration code. If it already ran in production, the data is gone. This only helps future deployments hitting that path.
